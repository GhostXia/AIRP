## 冲突标注与审计提示规范

cherry-pick 拆分时枢纽文件（`handlers/mod.rs`、`lib.rs`、`console-runtime.js`、`runtime-pages.test.mjs`、`chat-space.js` 等）易产生合并冲突。为让审计 Agent 独立复核人工合并的正确性，统一约定：

- **有手工冲突的 PR**：在 PR 评论（或主体）醒目点明每处冲突——含冲突文件、冲突双方来源、解决决策、审计要点。已执行：PR #317 评论（C1 `chat-space.js` / C2 `daemon/mod.rs` / C3 `council.rs`+`plot.rs` / C4 `director.rs` 测试）。
- **无手工冲突但含自动三方合并的 PR**：另开 issue 记录审计重点（hub 文件注册完整性、引擎模块导出），不写在 PR 描述主体里。已执行：issue #318（PR #316 Phase 2）。
- **纯单提交、无合并痕迹的 PR**：无需特别标注（如 PR #314 Phase 1）。

后续 PR D（Phase 4.2–4.6）、PR E（Phase 5.1–5.3）预计仍有同类冲突，沿用此规范。
