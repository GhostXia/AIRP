# PR #637 independent audit

Date: 2026-09-01

Scope: bound the responsive browser smoke's Vite, Chromium, and process-tree shutdown behavior (issue #630).

## Verdict

PASS. Two independent audit passes found no remaining blocker after the implementation adopted a stable Unix process-group leader, a bounded TERM window, and unconditional full-group KILL while that identity is still held. Windows uses bounded asynchronous `taskkill /t /f`. Primary test failures and cleanup failures remain independently observable.

## Evidence

- Node cleanup/supervisor tests: 6 passed on Windows; 3 Unix integration tests are selected for Linux CI.
- Vitest: 26 files, 205 tests passed.
- `vue-tsc --noEmit`: passed.
- Real Windows responsive smoke on isolated ports: passed; tested ports had no listener immediately after return.
- `git diff --check`: passed.

## Non-blocking follow-ups

1. Replace the supervisor's stderr exit marker with a dedicated IPC/control channel to eliminate diagnostic-output coupling.
2. Give externally terminated smoke runners a parent-death cleanup mechanism so a detached supervisor cannot become orphaned.
3. Add an automated Windows assertion that the smoke port is released after cleanup.
4. Replace the 5-second `browser.close()` race with shutdown ownership that can cancel or directly terminate Chromium; the current race bounds waiting but not Playwright's underlying close operation.
5. Use a monotonic clock in `waitForServer` instead of `Date.now()`.
6. Consider aligning Windows and Unix cleanup outcome names.

The post-KILL Unix zero-signal observation can theoretically see a rapidly reused PGID and report a false timeout, but it sends no further destructive signal and therefore cannot kill the reused group.
