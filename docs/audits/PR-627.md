## Scope and result

PR #627 adds bounded, read-only Emotion and Inventory projections derived from the current effective-root Character State. The Engine supplies revision, timestamp, and character-scoped provenance; the Vue widgets distinguish missing fields, invalid field values, and valid-empty Inventory and expose no write controls. Non-object Character State root semantics remain a documented follow-up below.

Both independent follow-up auditors found no remaining blocker and no blocker introduced by the fixes.

After the implementation verdict, `5748aea` changed only the responsive-smoke server lifecycle: Linux now starts npm/Vite in a detached process group and terminates that group, while Windows retains `taskkill /t /f`. An independent read-only follow-up audit approved the code, and the GitHub `UI and WebUI` job successfully exited with the responsive smoke enabled. The product implementation baseline above did not change.

## Closed blockers

1. Projection derivation now happens before the whole Character State props budget is applied. A large unrelated state field can truncate `core.character-state` without discarding valid Emotion or Inventory projections.
2. Projection provenance is constructed from the current typed Surface character instead of trusting source data embedded in state.
3. Projection-only changes produce adjacent patches for the stable Emotion and Inventory widget identities; cross-effective-root isolation is covered.
4. Manifest and UI parsing enforce an exclusive tagged union, reject unknown fields and illegal reasons, and agree with Engine producer behavior for object Character State. Missing or invalid Emotion fields never carry a label.
5. A valid maximum-Unicode Inventory that exceeds the per-widget byte budget degrades to schema-valid `available:false`, retaining revision, timestamp, and source.
6. Repeated Inventory instances cannot exhaust the Surface document budget: the first receives the complete projection and later instances receive metadata-preserving unavailable projections.
7. The widgets remain usable without horizontal overflow at 320, 760, and 761 CSS px under both 10/90 and 90/10 horizontal splits. Browser coverage checks the widget, header, and Inventory grid directly, plus meter ARIA and absence of write buttons. This smoke is part of the PR UI gate.
