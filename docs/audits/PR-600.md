# PR #600 independent audit

Date: 2026-08-26  
Scope: `codex/593-packaged-restart` against `origin/main`  
Auditor: independent Terra audit agent  
Final verdict: **PASS**

## Findings

The first audit identified three blocking findings: shutdown could win while
recovery was pending and leave the terminated instance's durable lock owner
behind; failure cleanup could terminate an unrelated process discovered by PID
or port; and the packaged smoke could write durable fixtures into an existing
portable package.

The Windows runner initially failed before recovery evidence because its
WebView2 process did not expose the requested CDP listener. The smoke now also
places WebView2's user-data folder inside the same unique temporary root, so an
existing runner profile cannot cause browser-process reuse that drops startup
arguments. The same auditor verified that both desktop launches use this
isolated profile and that final cleanup removes only the temporary root.

All three findings were corrected and re-audited by the same independent
auditor. Pending recovery now retains the exact terminated instance ID until a
replacement is published or shutdown takes cleanup ownership, with a focused
shutdown/recovery race regression. The smoke preflights both listener ports and
only terminates an Engine whose isolated executable path, lock port, recorded
shell PID, and parent PID all match processes launched by that smoke. Broad
port-owner termination was removed. The stateful WebView2 smoke now runs from a
unique temporary package copy that excludes any source `data/` directory and
removes the isolated root during cleanup.

The remaining bounded recovery path was found sound: stale termination events
cannot take a newer child, the restart budget is finite, the restarted Engine
receives the existing in-memory access key but the WebView receives a newly
exchanged short-lived token, and Vue reconnects in place without page reload or
automatic replay of dirty drafts.
