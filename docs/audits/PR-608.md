# PR #608 independent audit — Workspace-backed session Surface

Date: 2026-08-28

Auditor: independent default subagent (read-only; no LDR)

Final verdict: **PASS**

## Scope

PR 10d makes the saved `default` Workspace in the session's effective root
the Engine-side structural source for session Surface v2, while domain
services remain the only source of Widget props.

## First audit — FAIL

The first independent pass found three blockers:

1. Concurrent refreshes could publish an older Workspace layout after a newer
   one because the registry did not order publications by Workspace revision.
2. A future-major or invalid Workspace stopped Surface refresh but an old
   accepted Surface could still authorize intents indefinitely.
3. Documentation claimed every saved structural change emitted a snapshot,
   although Surface v2 cannot express `ratioBasisPoints` and ratio-only changes
   therefore produce no Surface event.

## Resolution

- `SurfaceRegistry` now records the accepted Workspace revision and ignores
  publications older than that authority revision. A ratio-only change still
  advances the internal Workspace authority even when the Surface revision and
  cursor remain unchanged.
- Every first-party Surface intent rereads the Workspace from the resolved
  effective root, requires the exact accepted revision, and reconfirms the
  Widget instance/type before any domain operation.
- The plan and current baseline now distinguish Surface-v2-expressible
  structural changes from ratio-only changes.
- Regression tests cover out-of-order publication, ratio-only authority
  advancement, props-only patch behavior, future-major intent revocation, and
  effective-root isolation.
- New-entry validation now occurs before LRU eviction, and the legacy default
  Surface builder/publication entry points are test-only.

The second independent pass found no remaining blocker and returned PASS.

## Non-blocking follow-ups

- **A1 · low · test hardening:** add an explicit intent rejection test for a
  corrupt Workspace manifest/hash. Future-major rejection is covered and both
  use the same `WorkspaceService::read()` fail-closed path.
- **A2 · medium · next Surface API touch:** reduce the chance of a caller
  pairing a Workspace revision with the wrong layout by having
  `publish_workspace` accept one validated document/value object instead of
  separate arguments. The only production caller currently passes both fields
  from the same validated `WorkspaceDocumentV1`.

Per repository policy, these follow-ups are filed as GitHub issues only after
the PR is merged.
