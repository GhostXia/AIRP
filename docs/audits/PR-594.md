## Findings and resolution

The first audit rejected the candidate for three blocking and two non-blocking
findings:

1. Character State was shared across sessions, but the UI patch only acquired
   the editing session's coordinator. The fix adds a daemon-local
   effective-root + character gate held by generation and state-replacing
   mutations, covers cross-session conflict in tests, and binds Agent
   state/lorebook tools to the trusted effective root derived at the HTTP
   boundary. Same-root generation blocks a whole-state tool write; different
   roots remain isolated.
2. Memory and Character State editors remained editable while saving. Both are
   now read-only for the in-flight request, preventing a successful response
   from overwriting newer local input.
3. Unknown mutation outcomes did not refresh authority. Every non-streaming
   Surface mutation error now attempts a read-only refresh without replay and
   preserves the user's draft against the refreshed baseline.
4. Memory accepted malformed expected hashes as conflicts. The Engine now
   requires exactly 64 lowercase hexadecimal SHA-256 characters and returns
   `400` otherwise.
5. Character State revision accepted strings in the manifest but integers in
   the Engine. Protocol, manifest, Engine, and UI now agree on a non-negative
   integer; the UI additionally rejects values outside JavaScript's safe
   integer range.

The final audit also confirmed the real-Engine browser smoke asserts that
Memory and Character State writes do not invoke the provider and do not rebuild
the unrelated Chat Widget Host.
