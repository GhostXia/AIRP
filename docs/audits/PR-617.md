## Final verdict

**PASS.** No blocking finding remains. The Engine-domain slice binds the
reviewed migration identity, creates and verifies a fixed-scope pre-migration
backup, preserves Workspace authority against generic restore, and reconciles
forward-commit durability without reporting an uncertain result as success.

## Audit history and resolutions

Eight independent review cycles were completed against fixed commits, followed
by a final report-bearing commit audit. The repository CodeRabbit gate also
performed an independent remote review.

1. Generic Full restore could replace Workspace assets; backup deletion could
   race between verify and commit; the plan bound only source hash; and commit
   failure exposed no structured retained-backup identity.
   - Full restore now rejects Workspace-bearing targets and its swap algorithm
     never removes, renames, or writes `ui/workspaces/`.
   - One `BACKUP_LOCK` lifetime spans create/verify/commit or
     verify/read/rollback-commit.
   - Apply binds source hash, candidate hash, and converter version.
   - Definite failure and outcome-unknown responses expose only a stable code,
     recovery category, and retained backup ID.
2. Full restore still had a check/use race with first Workspace creation; commit
   errors after pointer publication were incorrectly described as definite
   failure; and the authoritative lock contract was stale.
   - Full swap preserves Workspace at the path-operation level, independent of
     preflight timing.
   - Apply re-reads authority under the Workspace and Backup locks.
   - `docs/LOCK-ORDER-CONTRACT.md` records the sole
     `WORKSPACE_LOCK -> BACKUP_LOCK -> COMMIT_LOCK` edge.
3. Re-reading a published pointer proved visibility, not crash durability, and
   migration-backup rollback lacked the same unknown-outcome contract.
   - Test-only failpoints moved to the real atomic commit boundaries: after
     revision publication and after pointer publication but before final sync.
   - Apply and backup rollback now share reconciliation, verify layout plus
     source kind/hash/converter, renew durability barriers, and verify again.
4. First-created Workspace and backup directory entries were not fully synced
   through their stable parents on Unix.
   - Authority reconciliation syncs revision and revisions, re-syncs the
     pointer file, then syncs every directory from the asset to the effective
     data root bottom-up.
   - Backup publication syncs `backups/` and the data root after rename.
5. Nested backup staging directories were not individually synced before
   publication.
   - The complete staging directory tree is collected and synced deepest-first
     before rename; symlink entries fail closed.
6. The final fixed candidate passed review. The auditor confirmed nested file
   parents, manifest placement, empty backups, multiple directory branches,
   symlink handling, rename ordering, locks, structured errors, reconciliation,
   and forward-only rollback.
7. CodeRabbit then identified that Full restore changed child entries inside
   `ui/` without syncing that directory. The fix synced `current_ui` after all
   child removals/renames and synced the data root after top-level swap and
   staging cleanup. Follow-up independent review confirmed that fix, then found
   the same recursive-directory durability requirement in restore staging and
   the actual destination-parent chain for scoped restore.
8. Restore staging now uses the complete deepest-first directory-tree barrier.
   Character/Session scoped restore canonicalizes the destination parent and
   data root, then syncs each directory bottom-up through the root after rename.
   The final fixed candidate passed independent review with no blockers.

## Non-blocking follow-ups

- Harden staging traversal against a malicious external process with data-root
  write access by using directory-handle-relative/no-follow operations or a
  final pre-rename identity check.
- Windows `sync_dir` remains the documented no-op used by the existing backup
  and revision contracts; it does not claim Unix-equivalent power-loss
  durability.
- Strengthen backup durability tests with an actual sync-call trace and
  per-directory failure injection, not only deepest-first collection ordering.
- Return the retained `PreRestoreRollback` backup ID directly in generic restore
  failure responses instead of requiring operators to discover it by listing.
- Add a literal old-version backup-manifest JSON fixture for downgrade/read
  compatibility evidence.
- Define lifecycle/delete policy for internal migration recovery backups and,
  if product semantics require it, bind rollback selection to a migration
  lineage rather than accepting any valid older `pre_migration` point.
- If multi-process/direct writers are introduced, canonicalize the revision
  authority durability-root boundary and re-audit single-process lock assumptions.

These items do not block PR 10f-1 under AIRP's current single-process trusted
local-storage model. Per repository policy, unresolved audit suggestions must be
filed as deduplicated GitHub issues only after the PR is merged.
